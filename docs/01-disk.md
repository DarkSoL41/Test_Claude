# 1. Дискета, загрузчик и порядок запуска

## 1.1. Образ дискеты

`Supaplex (1991).adf` — стандартная дискета AmigaDOS OFS (880 КБ), метка тома
`SUPAPLEX`. Это «кракнутая» DOS-версия: оригинальный нестандартный загрузчик
заменён файловым. В бутблоке — текст «CRACKED TO DOS BY CRYSTAL / REMOVE WRITE
PROTECTION TO SAVE HI-SCORE IN FILE FORMAT».

| Файл | Размер | Загружается в | Содержимое |
|---|---|---|---|
| `S/Startup-Sequence` | 80 | — | запуск `CRYSTAL` |
| `CRYSTAL` | 4 120 | $40000 (после распаковки) | исполняемый hunk-файл крэка: распаковщик + загрузчик |
| `PHIL_00` | 107 520 | $54000 | интро: код ($54000–$54547) и три картинки с палитрами |
| `PHIL_01` | 94 208 | $7E00 | основная программа: код $7E00–$10FE3, далее данные и переменные |
| `PHIL_02` | 209 920 | $1EE00 | графика (тайлы, панель, меню, шрифты), музыка, демо |
| `PHIL_03` | 2 048 | $1BD94 | таблица рекордов и игроков (перезаписывается при сохранении) |
| `PHIL_10`…`PHIL_7E` | по 2 048 | $70000 → $12468 | 111 уровней (используются первые 1536 байт) |

## 1.2. CRYSTAL: распаковка ByteKiller

`CRYSTAL` — hunk-файл с одной секцией кода. Первые $E8 байт — распаковщик
**ByteKiller** (упаковка с конца файла к началу, контрольная сумма XOR);
реализация на Python — `tools/bytekiller.py`. Заголовок упакованных данных:
длина упакованного ($EE8), длина распакованного ($4060), контрольная сумма.
Результат кладётся в $40000, управление передаётся на $421C0.

Распакованный код ($421C0):

1. рисует текст крэка («SUPAPLEX / Another fine CRYSTAL crack! …»), ждёт кнопку мыши;
2. копирует свой файловый загрузчик в $50000 и процедуру записи в $7000;
3. переходит на $50000: там загружается `PHIL_00` в $54000 и запускается.

## 1.3. Файловый загрузчик крэка

Игра вызывает загрузку так же, как с оригинальной (нефайловой) дискетой: номер
«дорожки» в `d1`, адрес в `a0`. Крэк переводит номер в имя файла:

| d1 | Файл |
|---|---|
| $002 | PHIL_00 |
| $082 | PHIL_01 |
| $12C | PHIL_02 |
| $0FA | PHIL_03 |
| $226 + 2·(n−1) | уровень n: `PHIL_` + hex(n + $0F) |

Сам загрузчик — прямое чтение OFS с MFM-декодированием через DSKxxx/CIA-B
(в PHIL_01 копия по $10404, в PHIL_00 — по $54264). Процедура по $7000 пишет
2048 байт рекордов обратно в `PHIL_03`.

В порте эти процедуры заменены нативными (`native_loadFile`,
`native_saveHiscores`) — см. [5.6](05-port.md#56-что-сделано-нативно-и-почему-это-не-влияет-на-логику).

## 1.4. Интро (PHIL_00, $54000)

1. `intro_show_pictures` ($540A4): копирует три палитры в три copper-листа
   ($54672, $54706, $547D6) и выставляет указатели плоскостей
   (`intro_set_bitplanes`, `intro_copy_palettes`);
2. показывает картинку «Supaplex» (320×256, 4 плоскости, $548A6) 256 кадров,
   затем «A GAME BY» ($5E8C6, 320×200) и «PHILIP JESPERSEN + MICHAEL STOPP»
   ($665E6) по 101 кадру;
3. загружает `PHIL_01` в $7E00, ждёт таймер CIA и переходит на $7E00.

## 1.5. Запуск основной программы (PHIL_01, $7E00)

`main_entry` по порядку:

| Адрес | Подпрограмма | Действие |
|---|---|---|
| $840C | `init_hardware_base` | a5 = $DFF000, выключить фильтр (LED), копия указателя битмапа |
| $8446 | `relocate_pointer_table` | превращает таблицу смещений $1B5A0 в абсолютные адреса ресурсов PHIL_02 |
| $84F4 | `copylock_removed` | бывшая защита Copylock (крэком сведена к `clr.w $BE; rts`) |
| $845C | `load_graphics_and_hiscores` | загружает PHIL_02 в $1EE00 и PHIL_03 в $1BD94 |
| $8426 | `clear_irq_vectors` | все автовекторы → `rte` ($8444) |
| $898A | `unpack_hiscore_file` | раскладывает PHIL_03 по таблицам игроков/рекордов |
| $10AAA | `music_start` | запуск музыки меню |
| … | | построение меню, затем `main_menu` ($99C0) |

Дальше — вечный цикл «меню → уровень → меню» (см. [4. Логика игры](04-logic.md)).
