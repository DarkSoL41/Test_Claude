# 4. Логика игры (PHIL_01)

Имена подпрограмм — из [`tools/annotations.json`](../tools/annotations.json);
те же имена у функций порта и меток в [`disasm/PHIL_01.asm`](../disasm/PHIL_01.asm).
Адреса переменных — см. [2. Карта памяти](02-memory.md).

## 4.1. Карта уровня и кодирование клеток

Карта — 60×24 слова по адресу `$11928` (строка $78 байт). В каждом слове:

* **младший байт** (нечётный адрес) — тип клетки;
* **старший байт** (чётный адрес) — состояние/фаза объекта, который сейчас
  движется или взрывается.

Типы (совпадают с PC-версией; константы в $113B8…$113D5):

| Код | Объект | Код | Объект |
|---|---|---|---|
| $00 | пусто | $0D–$10 | «особые» порты →↓←↑ (с параметрами) |
| $01 | зонк (Zonk) | $11 | сник-снак (Snik Snak) |
| $02 | база (Base) | $12 | жёлтый диск |
| $03 | Murphy | $13 | терминал |
| $04 | инфотрон | $14 | красный диск |
| $05 | RAM-чип (все варианты после загрузки) | $15 | порт двусторонний ↕ |
| $06 | «железо» (все варианты после загрузки) | $16 | порт двусторонний ↔ |
| $07 | выход (Exit) | $17 | порт четырёхсторонний |
| $08 | оранжевый диск | $18 | электрон (при загрузке → $11 + свой список) |
| $09–$0C | порты →↓←↑ | $19 | баг (при загрузке → база $02 + список багов) |

Особые значения слова целиком:

| Значение | Смысл |
|---|---|
| `$8888` | клетка взрывается (занята взрывом) |
| `$7777` | соседняя клетка, задетая при гибели сник-снака (снимается на следующем кадре) |
| `$8011`, `$8022` | клетки, занятые движущимся сник-снаком/электроном (передняя и задняя половина) |
| `$EF01` | зонк падает в эту клетку; `$EB01` — клетка, из которой зонк падает |
| `$EE01` / `$ED01` | зонк скатывается влево / вправо в эту клетку |
| `$FF04` | инфотрон падает в клетку; `$FB04` — клетка, из которой он падает |
| `$FE04` / `$FD04` | инфотрон скатывается влево / вправо |
| `$FC04` | инфотрон, который Murphy «забирает не сходя с места» |
| `$EB08` | падающий оранжевый диск (обе клетки) |

## 4.2. Загрузка уровня

`main_menu` ($99C0) по кнопке огня загружает уровень (`native_loadFile`,
файл `PHIL_(n+$0F)`) в $70000 и копирует 1536 байт в `$12468`. Затем в
`main_entry`:

| Подпрограмма | Действие |
|---|---|
| `level_bytes_to_map` ($8BC8) | байты 60×24 → младшие байты слов карты `$11928` |
| `init_scroll_position` ($8D1C) | стартовая позиция экрана по Murphy (или из заголовка уровня) |
| `draw_whole_level` ($B20A) | блиттером рисует все 1440 клеток в битмап уровня |
| `build_object_lists` ($8BF2) | списки зонков, инфотронов (и их число → `$111CC`), сник-снаков, оранжевых и жёлтых дисков |
| `convert_special_tiles` ($8C84) | электроны → тип $11 + список `$18604`; красные диски → список; баги → база + список `$12738`; варианты чипов → $05, «железа» → $06 |
| `build_cell_address_table` ($B350) | для каждой клетки — адрес её 16×16 в битмапе уровня (`$191DE`) |
| `build_gfx_frame_table` ($B37C) | адреса кадров графики в листе тайлов (`$1A85E`) |

## 4.3. Кадр игры — `game_frame` ($B5A4)

Главный цикл (`main_entry`, $7EC8) вызывает `game_frame` каждый кадр, пока не
закончится уровень. Порядок внутри кадра (это важно для точности — объекты
обрабатываются строго в этой последовательности):

1. ждать начала кадра (`VHPOSR`), звук (`sound_frame`, `music_tick`);
2. каждый 50-й кадр — `tick_game_clock` (часы уровня ЧЧ:ММ:СС на панели);
3. отложенная очистка клетки после «взятия не сходя с места» (`$11322`, через 2 кадра);
4. `murphy_port_passage` — продолжение прохода через порт (2 клетки);
5. `update_murphy_tile_pos`, `$C9E8` — пересчёт клетки Murphy; если в ней
   опасный объект (сник-снак/электрон, падающий зонк или инфотрон) — гибель;
6. если уровень не завершается: `read_player_input` (джойстик/демо),
   гравитация (`$CB2C`), `murphy_move` — шаг Murphy;
7. проверка «раздавлен ли Murphy» приземлившимся объектом (`$11436`);
8. анимация падающих/скатывающихся инфотронов (`$E98E`) и зонков (`$E5E4`);
9. если враги не заморожены (`$14500`): сник-снаки (`$CF72`), электроны (`$D982`);
10. `update_bugs` ($B8B6), красный диск (`$EB32`),
    оранжевые диски (`$EBB6`);
11. через кадр — поиск новых падений зонков (`$E3B2`), иначе инфотронов (`$E786`);
12. взрывы (`$FC10`), счётчик простоя Murphy (`animate_idle_counter`),
    отложенная отрисовка Murphy (`blit_murphy_pending`), панель (`$FF9C`);
13. ждать строку 255.

Так как проверка падений идёт через кадр попеременно для зонков и инфотронов, а
анимация каждого шага длится 8 кадров (2 пикселя за кадр), все движения
синхронизированы с частотой кадров 50 Гц.

## 4.4. Murphy

### Ввод (`read_player_input`, $BAA0)

* Джойстик порта 2 (`JOY1DAT & $0303`): вверх `$0100`, влево `$0300`,
  вниз `$0001`, вправо `$0003`; диагонали игнорируются.
* В режиме демо (`$113AC`) слова ввода берутся из записанной таблицы (`$1B5C8`).
* Результат — `$118FE`: 1…4 = вверх/влево/вниз/вправо, 5…8 — то же с нажатой
  кнопкой огня («взять не сходя с места»).
* Кнопка огня без направления 30 кадров подряд на одной клетке при наличии
  красных дисков (`$113B2`) — Murphy закладывает красный диск.

### Шаг (`murphy_move`, $BC14)

Первый кадр шага выбирает обработчик по таблице `$11900`
(`murphy_start_up/left/down/right`, `murphy_snap_*`). Следующие кадры
продолжают начатое движение (`$11388` ≠ 0). Шаг длится 8 кадров по 2 пикселя;
одновременно двигается экран (скролл), когда Murphy подходит к краю видимой
области (переменные `$1133C/$1133E` — клетка Murphy на экране,
`$11340/$11342` — клетка левого верхнего угла, `$11344/$11346` — скролл в
пикселях).

Что происходит при попытке войти в клетку (для направления вверх; остальные
направления симметричны с учётом допустимых портов):

| В клетке | Результат |
|---|---|
| пусто, база, баг | шаг (база съедается; наступить на активного бага — гибель) |
| инфотрон (неподвижный) | шаг, инфотрон собран (`$111CC` − 1 при завершении) |
| движущийся инфотрон | стоп |
| красный диск | собран (`collect_red_disk`: отметка в списке, `$113B2` + 1), шаг |
| зонк, RAM-чип, «железо», оранжевый диск (вверх/вниз) | стоп |
| зонк / оранжевый диск (влево/вправо) | толкать: если клетка за ним пуста, нужно давить 15 кадров (`murphy_push_step`), затем объект и Murphy сдвигаются |
| жёлтый диск | толкается в любую сторону (так же, 15 кадров) |
| порт, пропускающий в этом направлении | если клетка за портом пуста — проход на 2 клетки (`murphy_port_passage`) |
| особый порт | то же + параметры из заголовка уровня: гравитация `$12A0C`, «заморозка зонков» `$12A25`, «заморозка врагов» `$14500` (`find_special_port`) |
| терминал | взрываются все жёлтые диски уровня |
| выход | если инфотронов не осталось (`$111CC` = 0) — уровень пройден (`$112D2` = 1) |

«Взять не сходя с места» (огонь + направление) работает для базы, инфотрона и
красного диска: 8 кадров анимации (`$113A8` до $20), затем клетка очищается.

### Гравитация (`$CB2C`)

Если в уровне (или после особого порта) включена гравитация и под Murphy пусто,
направление принудительно заменяется на «вниз», а ввод блокируется (`$1134C`).
Исключения: Murphy уже в движении; сбоку база и Murphy идёт на неё; над ним
порт ↑; над ним база и нажато вверх или вниз.

### Гибель (`$F21A`)

Флаг `$112DA` выставляют: сник-снак/электрон рядом или в клетке Murphy,
приземление зонка/инфотрона на голову, взрыв, задевший Murphy, шаг на
активного бага. Гибель: звуковой эффект, клетки 3×3 вокруг Murphy (кроме
«железа») помечаются `$8888`, проигрывается анимация взрыва; счётчик `$112D4`
растёт на 2 за кадр, по достижении $12 уровень заканчивается и игра
возвращается в меню.

### Закладка красного диска

Кнопка огня без направления, удерживаемая 30 кадров на одной клетке
(`$11392`, клетка запоминается в `$11394`), при наличии красных дисков
(`$113B2` > 0) закладывает диск в клетку Murphy (`$1138E` = 1, см. 4.7). В
режиме демо кнопка огня не используется.

### Края карты (если убрать рамку из «железа»)

Проверено на оригинальном коде (эталонный эмулятор, рамка убрана записью
в память во время уровня):

* **Murphy за край не выходит ни в какую сторону.** Его шаг привязан к
  экрану и прокрутке: влево — стоп при экранном столбце 1 и минимальной
  прокрутке ($C0B4), вправо — при столбце 19 и максимальной ($C4BC), вверх —
  при строке 1 и `v_scroll_y` = 0 ($BEB0), вниз — при строке 11 и
  `v_scroll_y` = $B0 ($C2C2). Поэтому Murphy ходит только по клеткам
  x = 1…58, y = 1…22, даже если клетки рамки пусты; «перехода на другую
  сторону», как в DOS-версии, нет.
* **Но только при правильной стартовой камере.** Стоп требует, чтобы
  прокрутка была *ровно* минимальной или максимальной. Если камера из
  заголовка уровня (байты 1440–1443) уводит экран за карту, прокрутка
  оказывается вне этих пределов, равенство не наступает никогда, и Murphy
  уходит за край уровня — в память над или под картой (замечено
  пользователем на порте; порт исполняет код игры один в один). Поэтому
  редактор считает камеру за картой ошибкой.
* **Остальные объекты границ не проверяют**: соседние клетки берутся как
  ±2 и ±120 байт от текущей, то есть для них карта — одна лента построчно,
  как в DOS. Над картой (строка −1, $118B0–$11927) лежат переменные игры:
  таблица смещений строк, `v_input_dir` и таблица обработчиков шага Murphy
  ($11900) — объект, попавший туда, портит их. Под картой — буфер уровня
  $12468 (после разбора уровня обнулён, 12 строк «пустоты»), затем заголовок
  уровня и таблица особых портов.
* Опыт: уровень 1, убрана клетка рамки под зонком (23, 22) — весь столбец
  зонков провалился вниз сквозь дыру в пустоту под картой; через ~2 с
  оригинальная игра зависла (процессор ушёл на мусор по адресу $1A8A):
  картинка уровня занимает $52000–$7EFFF, и клетки ниже 23-й строки
  рисуются уже в стек ($7F000) и дальше.

## 4.5. Зонки и инфотроны

Каждый зонк и инфотрон есть в своём списке (4 байта: состояние, фаза
анимации, смещение клетки ×4). Движущиеся объекты дополнительно попадают в
списки анимации (`$163D4` — зонки, `$17E32` — инфотроны; 8 байт на запись).

**Поиск начала движения** (`$E3E2` для зонков — через кадр, `$E786` для
инфотронов — в другие кадры). Для каждого неподвижного объекта:

1. если его клетка взрывается (`$8888`) — объект уничтожен;
2. под ним пусто (или уходящий сник-снак `$8022`) → **падение**;
3. под ним зонк, инфотрон или RAM-чип → **скатывание**: сначала проверяется
   левая сторона (слева и слева-снизу пусто), затем правая; клетка-цель
   помечается `$EE01/$ED01` (`$FE04/$FD04`);
4. под ним сник-снак — он взрывается (`$8888`), соседние части `$7777`.

**Анимация** (`$E5E4`, `$E98E`): падение — 8 фаз по 2 пикселя (таблицы
обработчиков `$11210` / `$11250`), на последней фазе объект переносится в
нижнюю клетку. Если он приземлился на оранжевый диск — диск взрывается; если
на Murphy — Murphy раздавлен (кроме случая, когда Murphy как раз уходит в
сторону). Скатывание — 8 фаз (`$1C` в байте фазы), затем объект переходит в
соседнюю клетку.

**Заморозка зонков** (`$12A25`, из уровня или особого порта): 1 — зонки
обрабатываются упрощённой веткой ($E4AC) и инфотроны тоже ($E87A);
2 — зонки не обрабатываются вовсе.

## 4.6. Сник-снаки и электроны

Список сник-снаков `$1821C` и электронов `$18604` — по 8 байт:

| Смещение | Смысл |
|---|---|
| +0 | фаза шага (0…8) |
| +1 | состояние: 1 ↑, 2 ←, 3 →, 4 ↓ — движется; 5/6/7/8 — только что закончил шаг вверх/влево/вниз/вправо; 0 — не двигался |
| +2 | смещение клетки ×4 |
| +4 | поворот в процессе (задержка) |
| +5 | направление последнего шага |
| +6, +7 | признак и фаза анимации поворота (8 ориентаций) |

Правило движения (`$CF72` и аналогичный `$D982`) — «держаться левой стены»:
после шага в направлении D враг проверяет клетки в порядке **налево от D,
прямо, направо, назад** и идёт в первую пустую. Если в проверяемой клетке
Murphy — Murphy гибнет. Если направление меняется, сначала проигрывается
анимация поворота (по одной фазе на несколько кадров). Если все четыре
стороны заняты — враг крутится на месте. Во время шага враг занимает обе
клетки (`$8011` + `$8022`). Попадание во взрыв (`$8888`) уничтожает врага с
новым взрывом (электрон взрывается «в инфотроны»: клетки 3×3 после взрыва
становятся инфотронами, флаг `$112E8`).

## 4.7. Диски

* **Оранжевый** (список `$189EE`, по 6 байт: пиксельное смещение падения,
  клетка, задержка, состояние): падает, если под ним пусто (8 фаз, клетки
  `$EB08`); приземлившись на что угодно — взрывается в нижней клетке. Задетый
  взрывом — взрывается через 10 кадров. Murphy толкает его влево/вправо.
* **Жёлтый** (список `$191C0`): Murphy толкает в любую сторону; все жёлтые
  диски взрываются, когда Murphy касается терминала (`$C91C`). Задетый взрывом
  исчезает из списка.
* **Красный**: собирается Murphy (`$113B2` — запас). Заложенный диск (огонь без
  направления 30 кадров) лежит в клетке Murphy и через 35 кадров взрывается
  (`$EB32`).

## 4.8. Баги (`update_bugs`, $B8B6)

Раз в 4 кадра берётся очередной баг из списка `$12738`. Если его клетка —
база, баг «вспыхивает»: клетка становится типа $19, 5 фаз анимации вперёд и 5
назад, затем снова база и ход переходит к следующему багу. Одновременно
активен только один баг. Шаг Murphy на активный баг — гибель.

## 4.9. Взрывы (`$F8E6`, `$FC10`)

До 12 одновременных взрывов (таблица `$1B1E2`, по $30 байт: счётчик задержки,
фаза, 9 адресов клеток в битмапе, указатель центра, признак «в инфотроны»).
Взрыв 3×3: «железо» (6) и уже взрывающиеся клетки не затрагиваются; движущиеся
объекты (слова ≥ $9000) — в зависимости от позиции соседа (в оригинале списки
исключений у соседних клеток отличаются, это сохранено). Murphy в зоне взрыва
гибнет. Анимация — 8 фаз по 4 кадра, всё это время клетки держатся `$8888`,
затем очищаются (или становятся инфотронами). Взрыв сопровождается звуковым
эффектом (канал блокируется для музыки на 10 кадров).

## 4.10. Экран

* Битмап уровня — 960×384, 4 плоскости interleaved (120 байт на строку
  плоскости, $1E00 байт на ряд клеток). Вся отрисовка — копирование блиттером
  16×16 кадров из листа тайлов (`$1A85E` — таблица адресов кадров) по адресам
  клеток (`$191DE`).
* Видимая часть — окно 320×208 (13 клеток по вертикали) + панель статуса;
  прокрутка — указателями плоскостей в copper-листе `$1B6BE` и BPLCON1
  (`$CE62/$CE90/$CEBE/$CEF2` — сдвиг на пиксель вверх/вниз/влево/вправо).
* Панель: имя игрока, номер и название уровня, часы, число оставшихся
  инфотронов (`$FF9C`), красные диски.

## 4.11. Меню, игроки и рекорды

* `main_menu` ($99C0): указатель мыши — аппаратный спрайт 0; клик ищется по
  таблице зон `$1B422` (15 прямоугольников → обработчики: новый/удалить игрока,
  пропуск уровня, статистика, «gfx-tutor», демо, прокрутка списков, OK и т.д.).
* Огонь джойстика запускает выбранный уровень (`$140DC` — индекс; доступны
  уровни до максимального пройденного, `+$14` в записи игрока).
* Имя нового игрока вводится с клавиатуры (`$9CD0`: перекодировка сканкодов
  по таблице `$1B4D6`, Backspace — стереть, Return — готово).
* Рекорды и игроки хранятся в `PHIL_03` (см. [6. Форматы](06-formats.md)) и
  записываются на дискету после изменения (`save_hiscores`).

## 4.12. Звук

Музыка — трекерный модуль (15 инструментов, формат Soundtracker/Protracker без
сигнатуры), плеер в прерывании кадровой развёртки (`vertical_blank_interrupt`
→ `music_tick`, новая строка паттерна каждые 6 кадров). Звуковые эффекты
занимают канал на заданное число кадров (`sound_effect_lock`, $10B56): пока
канал занят эффектом, плеер пишет его регистры в «пустое место» ($111AE).
